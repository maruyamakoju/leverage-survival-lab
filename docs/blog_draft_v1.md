# 100倍レバは数学的に詰んでいる ── 87,325 回のバックテストで証明する

## TL;DR

Binance USDT-M Perpetual の BTC/USDT 過去 6 年分(2020-01〜2026-05)を使い、**87,325 回のモンテカルロ・バックテスト**を実行した。

結果:

- **100倍レバレッジの 30 日生存率は 0.0%**(N=499 × 5戦略 × 5損切水準 = 12,475 サンプル)
- 95% Wilson 信頼区間の上限: **0.76%**
- 損切ルール(-0.5% / -1% / -2% / -5% / なし)を変えても結果は同じ
- ナイーブ戦略(SMA / RSI / Bollinger / Breakout)とランダムエントリーで有意差なし

つまり「適切な損切で100倍レバでも勝てる」というナラティブは、データ上は完全に否定される。コードは MIT で全公開:[github.com/maruyamakoju/leverage-survival-lab](https://github.com/maruyamakoju/leverage-survival-lab)

---

## なぜこれをやったか

仮想通貨の SNS には「100倍レバ × 損切ルール」で個人投資家が勝てるという主張が定期的に流れる。一方、Binance Futures の 90 日資金消失率は 80〜90% という業界推計もある。

定性的には「無理」と分かっているが、**定量的・統計的な反証データが日本語圏でほぼ存在しない**。この空白を埋める。

副次的な目的:

- Claude Code を使った長時間自律エージェント運用の実証研究
- 定量金融の実装スキルとバイアス対策のリファレンス実装

実弾(現金)は1円も投入していない。すべて自前シミュレータ上の実験。

- **H3**: 戦略エッジは10〜20倍で消失

## システム設計

5 層アーキテクチャ:

```
L5  Claude Code Agent  — 仮説生成→実装→実行→分析の自走
L4  Analysis           — Sharpe / DD / Risk of Ruin / 可視化
L3  Backtest Runner    — モンテカルロ・グリッド + 並列実行
L2  Leverage Engine    — 証拠金 / 清算 / 手数料 / ファンディング
L1  Data               — Binance/Bybit OHLCV + Funding (Parquet)
```

### レバレッジエンジン(L2)

市販のバックテストツールはレバレッジ清算を厳密にモデル化していないことが多い。本実装で重視したポイント:

1. **清算判定をバー内で行う**(終値だけでは清算が起きない見せかけが起きる)
2. **手数料を片道ごとに区別**(Binance USDT-M Perp の VIP0 デフォルト: taker 0.04%, maker 0.02%)
3. **スリッページモデル**(ストップ約定時は追加スリップ +0.05%)
4. **ファンディングレート**を実データから 8 時間ごとに適用
5. **Isolated 証拠金で equity を 0 でクランプ**(手数料負担で負にならないように)

清算価格(Long, Isolated):

```python
p_liq = entry * (1 - (1/L - mm))
# 100x, mm=0.5% → 0.5% 下落で清算
```

### バックテストランナー(L3)

look-ahead bias 防止のため、シグナルは bar `t` の close で生成し、約定は bar `t+1` の **open** で行う。これをエンジン側で強制し、戦略実装者がうっかり違反するのを防ぐ。

清算判定は当該バーの High/Low で行う(終値だけでは清算が無視される)。

### モンテカルロ・グリッド(L3+)

独立変数:

- レバレッジ: {1, 2, 5, 10, 25, 50, 100}
- 損切ライン: {-0.5%, -1%, -2%, -5%, なし}
- 利確ライン: {なし}(本実験では未使用)
- 戦略: {Random / SMA(20,50) / RSI(14) / Bollinger(20, 2σ) / Breakout(20)}
- 抽出窓: 過去 6 年から 30 日窓を 500 個ランダム抽出(seed=42)

合計: **7 × 5 × 1 × 5 × 499 = 87,325 シミュレーション**

## 結果

### H1: 100倍レバの 30 日生存率

すべての (戦略, 損切) セルで生存率 0%、CI 上限 0.76%。

| Leverage | Survival | 95% CI | 平均終端残高(USDT) |
|---------:|---------:|:------:|--------------------:|
|  1x | 100.0% | [99.2%, 100%] | 1,049,xxx |
|  2x |  99.8% | [98.9%, 100%] | 1,103,xxx |
|  5x |  93.7% | ... | ~1.2M |
| 10x |  72.8% | ... | bimodal |
| 25x |   0.0% | [0%, 0.76%] | 0 |
| 50x |   0.0% | [0%, 0.76%] | 0 |
|**100x**|**0.0%**|**[0%, 0.76%]** | **0** |

### H2: 損切ラインの最適点

中レバ域(5x, 10x)では内点解(-1% 〜 -2%)が見られた。極端にタイトな -0.5% は whipsaw で削られ、緩い損切は強制ロスカットで一発死。

低レバ(1x, 2x)はそもそも清算が起きないため、損切水準は重要でない。
高レバ(25x+)はどの損切水準でも全滅。

### H3: 戦略エッジの消失閾値 — 衝撃の事実

H3 は「正のシャープを持つ戦略が、レバを上げると期待値マイナスに転じる閾値があるか」を問うていた。

ところが **レバ 1x でも全戦略が負の平均 log-return** を示した。理由: 取引手数料(片道 taker 0.04% + slip 0.05% = 0.09%)が累積で edge を相殺してしまう。

つまり、これらナイーブ戦略はそもそもエッジを持たない。レバを上げる前に手数料で死んでいる。

| 戦略 | レバ1xでの平均log-return |
|------|------------------:|
| bollinger | -5.4% |
| breakout  | -1.6% |
| random    | -3.5% |
| rsi       | -2.1% |
| sma_cross | -3.6% |

### Bonus: ポジションサイズを抑えても 100倍は救えない

「100倍レバを使うが、口座の 5% しか張らない」は救いになるか?

risk_fraction を {1.0, 0.5, 0.25, 0.10, 0.05} で sweep した結果:

| risk_fraction | 100x の30日生存率 | 95% CI |
|---------------|-----------------:|--------|
| 1.00 | 0.0% | [0%, 0.76%] |
| 0.50 | 0.0% | [0%, 0.76%] |
| 0.25 | 0.0% | [0%, 0.76%] |
| 0.10 | 0.0% | [0%, 0.76%] |
| **0.05** | **0.0%** | **[0%, 0.76%]** |

理由: 30日の間に 5% 確率/バー × 720時間 = 約70回エントリーがある。各エントリーは 100倍レバで 0.5% 程度の逆行で清算される。1回ごとの損失は IM(=口座の 5%)に限定されるが、70回の累積で口座は枯渇する。

**「ポジションサイズを小さくすれば100倍レバでも安全」というアドバイスは、トレード頻度を考慮した瞬間に破綻する。**

### H4: 高レバでは戦略の差は消える

50x, 100x で各戦略 vs ランダム の 2 比率 z 検定 + Bonferroni 補正:

すべてのペアで p=1.0(両者とも 0% 生存)。**戦略の優位性はレバレッジによって完全に相殺される**。

## 結論

**「適切な損切で100倍レバでも勝てる」という主張は、87,325 回の検証の結果、データ上は支持されない。**

具体的には、

1. **100x の30日生存率は 0% で、95% CI 上限が 1% を下回る**
2. **戦略の優劣はレバが上がると消滅し、ランダムと有意差なし**
3. **そもそも検証した 5 戦略はレバ 1x でも手数料負担で負の期待値**

これは「個人投資家の高レバ取引は本質的に不利」という業界推計と整合する。
