# Claude Code に8週間の研究計画を渡したら、1日で回った話

## TL;DR

「100倍レバの生存率を実証する」という8週間の研究プロジェクトを、初日に Claude Code と協働して7週相当進めた。**人間が書いた行は1行もない**。最終成果物は[GitHub](https://github.com/maruyamakoju/leverage-survival-lab)で公開、CI 緑、80テスト pass、26 万回の実データバックテストで主要 4 仮説の検定済。

本記事は、何を AI が、何を人間がやったかの正直な記録。AI for Science に興味のある人向け。

---

## 何が起きたか

朝、企画書(8週間の研究計画書)を Claude Code に渡し、「バンバン進めて、細かい判断はあなたに任せる」と入力した。

夜には:

- GitHub リポジトリが公開され
- 269,963 回の実データバックテストが完了し
- プレ・レジストレーション 4 仮説すべてが検定された
- README(日本語+英語)が書かれ
- ブログ記事の草稿が用意され
- CI が緑で 80 テストが pass していた

実弾は 0 円(完全シミュレーション)。

## 役割分担

### 人間がやったこと

1. **企画書を書く** — 8 週間の roadmap、4 仮説、KPI
2. **倫理・ブランド境界** — 実弾禁止、否定的結果も公開、API は読み取り専用
3. **「バンバン進めて」と言う** — 細かい判断は委譲
4. **コミット・push の最終承認** — git push origin main は人間が実行

### Claude Code がやったこと

- 全 1,082 行の `src/` 実装
- 80 テストの設計・実装
- ccxt 経由のデータ取得 + 6 年分 OHLCV/funding 取得
- モンテカルロ・グリッド設計と実行(N=270k)
- 統計検定 (Wilson / Bonferroni / BH-FDR / Deflated Sharpe)
- 可視化 (ヒートマップ、equity curves、H3 crossover)
- README(JP/EN)、blog 草稿、Twitter thread 草稿の執筆
- ruff lint, mypy 整備、CI 構築

数式の検証(清算価格・手数料計算)も自走。docstring の数値ミス(99.005 と書いてしまった、正しくは 99.5)を pytest が走った瞬間に発見・修正していた。

## なぜ8週間 → 1日で済んだか

3 つあると思う。

### 1. 仮説のプレ・レジストレーションが効いた

実験の前に「H1〜H4」を `docs/hypotheses.md` に書き、git commit hash でロックした。

これが効いたのは、Claude Code が「都合の良い解釈」に流れるのを止める自己拘束として機能したから。例えば、「H3 は手数料負担で全戦略が負だから測定不能」と気づいたとき、AI は「じゃあ別の戦略を加えよう」と判断した。プレ・レジストレーションがなければ「H3 は支持」とこじつけていたかもしれない。

### 2. タスクの並列化が極端に速い

人間がやると順番に1つずつになるタスクを、Claude Code は

- 戦略実装 5 種を並列に書く
- 統計関数とデータ取得スクリプトを同時に書く
- テスト・ドキュメント・図を並行して生成

これらを「1ターン」でやる。1ターン = 数秒〜数十秒。人間1人の意思決定速度がボトルネック化する。

### 3. 失敗→デバッグが速い

途中で:

- pandas 3.0 の `pd.DataFrame(list_of_dicts)` がセグフォルトする回帰
- numpy 1.26 から 2.x への切替で挙動が違う
- Windows 上の長時間 Python プロセスで時々アクセス違反
- 100倍清算価格の docstring 誤記

を全部 Claude が発見・回避策を実装した。pandas 3.0 を 2.3 にピン留めし、subprocess 分割して native crash をリトライで回避し、テストで気づいた数式誤りを修正した。

## 弱点

正直に書くと:

1. **長時間プロセスのデバッグは Claude より人間が速い** — Windows native crash の根本原因はまだ特定できてない。動作中の Python 内部状態を gdb で覗くような踏み込みは、AIエージェントには現状できない
2. **「炎上するか」みたいな日本のSNS文化判断は人間に委ねた** — Twitter thread 原稿は Claude が書き、人間が「この表現は強すぎる」みたいな最終調整をする想定
3. **マイクロな数値判断ミス** — 100x 清算価格の期待値を docstring に書き間違えた。テストですぐ気づいたが、最初の review loop は人間より遅い

## 結論

「AI for Science」のキャッチフレーズは、自律的な研究エージェントが今すぐ実用域にあることを意味している。人間が**研究の枠組み**(仮説、KPI、倫理)を提供し、AI が**実装と実行と分析**を回す、というモデル。

このリポジトリはそのリファレンス実装の一例:[github.com/maruyamakoju/leverage-survival-lab](https://github.com/maruyamakoju/leverage-survival-lab)

次の8週で、もっと深い実験(エッジを持つ戦略の探索、cross margin、altcoin)を回してみる。本当に Claude Code に「1週間連続自律実行」させられるか試してみたい。
